## 1. ปัญหาที่จะแก้

เมืองทองธานีมีงานจัดต่อเนื่องเกือบทุกวัน แต่ข้อมูลกระจัดกระจายและไม่ได้ออกแบบมาเพื่อการตัดสินใจของคน 3 กลุ่ม:

| กลุ่ม | คำถามที่ต้องการคำตอบ | วันนี้ตอบได้ไหม |
|---|---|---|
| **ร้านค้าในพื้นที่** | สัปดาห์หน้าพีคไหม ต้องสั่งของ/จ้างคนเท่าไร | ❌ ต้องไล่ดูปฏิทินเองทีละงาน |
| **คนที่อยากมาชมงาน** | เร็ว ๆ นี้มีงานอะไร ฟรีไหม พาเด็กไปได้ไหม | ⚠️ มีปฏิทิน แต่ไม่บอกฮอลล์/เวลา/กลุ่มเป้าหมาย |
| **คนที่ต้องผ่านเส้นทางนี้** | วันนี้หนักไหม หลบช่วงไหน | ❌ ต้องเดาจากประสบการณ์ |

## 2. ข้อค้นพบฐาน (ตรวจวัดจริง 23–24 ต.ค. 2026)

จากปฏิทินอิมแพ็ค 25 งาน (23 ต.ค. – 13 ธ.ค. 2026):

- **45 จาก 52 วันมีงาน (87%)** — เฉลี่ย ~2 งานต่อวันที่มีงาน
- วันที่งานซ้อนสูงสุด **7 งาน/วัน (7 พ.ย. 2026)**
- **ต่อเนื่อง 12 วันติด (2–13 ธ.ค.)** — Motor Show + งานฮาร์ดแวร์
- วันว่างจริงมีเพียง **7 วัน**: 2, 9, 10, 18, 29, 30 พ.ย. และ 1 ธ.ค.
- ช่องว่างข้อมูล: ปฏิทินไม่บอกฮอลล์ · ไม่มีงานไกลกว่า 2 เดือน (Stray Kids 16–17 ม.ค. 2027 ไม่ปรากฏ) · ไม่มีงานใน Cosmo/Beehive/โรงแรม · ไม่มีจำนวนคน · ฟีด RSS ค้างปี 2023 · ไม่มี iCal/API

> รายละเอียดหลักฐานทั้งหมดอยู่ใน [`DATA_SOURCES.md`](DATA_SOURCES.md)

## 3. สิ่งที่สร้าง

**ฐานข้อมูลเดียว → 3 ทางออก**

```
                    ┌──────────────────────────┐
  แหล่งข้อมูล 4 ชั้น → │   ImpactGo Data Core     │ → Excel (ร้านค้า)
                    │  event · venue · score    │ → เว็บ/การ์ด (คนมาชมงาน)
                    └──────────────────────────┘ → LINE (รายสัปดาห์)
```

1. **Excel/ชีต** — ปฏิทินพีค 6 สัปดาห์ พร้อมคะแนนความหนาแน่น (ร้านค้าพิมพ์ใช้)
2. **เว็บหน้าเดียว** — ปฏิทินกรองได้ + การ์ด "วันนี้/พรุ่งนี้" (คนมาชมงาน + คนผ่าน)
3. **LINE** — สรุปสัปดาห์ละครั้ง + แจ้งงานใหม่/งานยกเลิก (ตัวกระตุ้นให้กลับมาใช้)

## 4. ขอบเขต MVP (4 สัปดาห์)

**ทำ:** ดึงข้อมูลอัตโนมัติวันละ 2 ครั้ง · รวม 4 แหล่ง · แปลงอาคาร/ประเภทงาน · ให้คะแนน 0–4 รายวัน · ช่วงชั่วโมงเสี่ยง · Excel + เว็บ + LINE · หน้าตรวจสอบข้อมูล (human-in-the-loop)

**ไม่ทำใน MVP:** พยากรณ์จากเซนเซอร์/กล้อง · ซื้อขายบัตร · แจ้งเตือนเรียลไทม์รายนาที · แอปมือถือ · navigation ในพื้นที่ · เก็บข้อมูลส่วนบุคคล

## เริ่มใช้งาน (ฉบับนักพัฒนา)

```bash
cd /Users/ken/impactgo
./run.sh            # ดึงปฏิทิน + คำนวณระดับ + สร้างเว็บ (~10 วินาที)
./serve.sh          # เปิด http://localhost:8080
./admin.sh          # หน้า curator http://localhost:8081 (รวม/แยก/ยกเลิกงานรอตรวจ)
python3 tests/test_parse.py   # ทดสอบ parser ด้วย snapshot จริง
```

ผลลัพธ์:
- `site/index.html` — หน้าเว็บ (8 สัปดาห์ + heatmap + ตัวกรอง)
- `site/events.ics` — ปฏิทินทั้งชุด / `site/ics/<id>.ics` — รายงาน
- `data/impactgo.db` — ฐานข้อมูล SQLite
- `data/snapshots/` — HTML ดิบที่ดึงมา (ตรวจย้อนได้)

ตั้งเวลาให้รันเอง (cron 06:00 และ 12:00):
```
0 6,12 * * * cd /Users/ken/impactgo && ./run.sh >> data/cron.log 2>&1
```

## 6. เกณฑ์ความสำเร็จแบบเห็นได้

- ข้อมูลใหม่ภายใน **24 ชั่วโมง** หลังประกาศ
- ครอบคลุมงานสาธารณะ **≥ 85%** เทียบการตรวจนับด้วยมือ 2 สัปดาห์
- ร้านค้านำร่อง **10 ร้าน** ใช้รายงาน ≥ 3 สัปดาห์ติด
- ประกาศพีคผิด (false peak) **< 10%**
- ต้นทุนดำเนินการ **< 1,500 บาท/เดือน**
